Related links, notices or upcoming events.

Purpose of semantic elements

  • <header>: introductory content for a page or section.
  • <nav>: a major group of navigation links.
  • <main>: the main, unique content of the document.
  • <section>: a thematic group of related content, usually with a heading.
  • <article>: self-contained content that could stand on its own.
  • <aside>: related or supplementary content.
  • <footer>: closing information for a page or section.

Semantic structure is better than using generic containers everywhere because it gives content meaningful roles, improves document readability and can help browsers, search engines and assistive technologies interpret the page. A <div> is still useful when no semantic element fits.

Character Entity Challenge

Correct display of mathematical symbols, copyright, quotation marks and special characters.

&lt; → <

Less-than sign; avoids confusing text with an HTML tag.

&gt; → >

Greater-than sign; useful in comparisons and examples.

&amp; → &

Ampersand; also used to begin named entities.

&copy; → ©

Copyright symbol for copyright notices.

&quot; → "

Quotation mark; useful when a quote must be represented in markup.

&apos; → '

Apostrophe character represented as a named entity.

&nbsp; → A B

Non-breaking space keeps adjacent words together.

&times; → ×

Multiplication sign.

&divide; → ÷

Division sign.

&le; → ≤ and &ge; → ≥

Less-than-or-equal and greater-than-or-equal signs.

&trade; → ™

Trademark symbol.

&euro; → €

Euro currency symbol.

Example expression

For all x ∈ real numbers, if x ≥ 0 and x < 10, then x × 2 ≤ 18 for x ≤ 9.

Character references are useful when a character has special meaning in HTML syntax or when a symbol is not easy to type. Most modern documents should use UTF-8, which supports a wide range of characters directly, but entities remain useful for reserved markup characters and readable examples.

Q8

Frames: Old Approach vs Modern Design

Comparison of traditional frames/framesets and a modern semantic, CSS-based layout.

Traditional frames / frameset

Older HTML used <frameset> and <frame> to split a browser window into separate independently loaded documents.

  • Each frame could load a different HTML page.
  • Navigation and content could scroll independently.
  • Frames often made bookmarking, history, responsive layouts and accessibility harder.
  • <frameset> and <frame> are obsolete in HTML5 and should not be used for new pages.

Modern HTML5 + CSS

Use semantic HTML for meaning and CSS Grid/Flexbox for page layout.

  • Use <header>, <nav>, <main>, <aside> and <footer> where appropriate.
  • Use CSS to create columns and responsive layouts.
  • Use regular links for navigation and meaningful headings for structure.
  • Use an <iframe> only when embedding a separate resource is genuinely required.

Example modern page structure

<header>Department header</header>
<nav aria-label="Main navigation">Navigation links</nav>
<main class="layout">
  <article>Main page content</article>
  <aside>Related information</aside>
</main>
<footer>Contact and copyright</footer>

/* CSS idea */
.layout {
  display: grid;
  grid-template-columns: minmax(0, 2fr) minmax(200px, 1fr);
  gap: 1rem;
}

Conclusion: modern semantic HTML and CSS provide a flexible, responsive and accessible structure without dividing the browser window into obsolete frames. A media query can stack the columns on smaller screens.
